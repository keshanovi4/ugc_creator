# Размещение на Fly.io

Текущий адрес: [ugc-creator-keshanovi4.fly.dev](https://ugc-creator-keshanovi4.fly.dev). Сейчас он **только перенаправляет в основной кабинет**, работающий на компьютере владельца. В Fly Secrets оставлен CANONICAL_URL. Обработчик бота и база на Fly не запускаются; старые API и POST возвращают 409. Это исключает отдельную очередь со старыми данными.

До отключения сохранены согласованные копии обеих баз. Уникальных заявок на Fly не обнаружено. SN-0001 и SN-0002 находятся в основной локальной базе. Секреты бота и подключений удалены из окружения Fly; зашифрованная старая база на Volume сохранена для восстановления.

## Конфигурация

Приложение ugc-creator-keshanovi4, регион ams; одна Machine shared CPU / 512 МБ; Volume ugc_data 1 ГБ, путь /app/data. Параметры — fly.toml. Dockerfile.fly назначает владельцем каталога Volume пользователя node, затем запускает Node с UID 1000 через su-exec. Обычный Dockerfile и защищённый Compose не изменены.

Для режима перенаправления в Fly Secrets задаётся CANONICAL_URL — только HTTPS origin основного кабинета, без пути, логина или пароля. Нельзя указывать собственный адрес: это предотвращает цикл. При смене локального туннеля обновите CANONICAL_URL. Перенаправление не открывает SQLite и не требует секретов интеграций.

## Перенос единственной базы на постоянный сервер

После отдельного решения владельца о хостинге:

1. Остановить приём на прежнем сервере и сделать финальную SQLite backup. Не копировать открытый файл обычной командой и не заменять работающую базу.
2. Загрузить согласованную базу на Volume с правами 0600. Сохранить прежний ключ шифрования подключений в защищённом хранилище; без него потребуется повторное подключение Threads и Gemini.
3. Задать BOT_TOKEN, ADMIN_IDS, SESSION_SECRET, TELEGRAM_WEBHOOK_SECRET и INTEGRATION_SECRET. DATABASE_PATH должен указывать на перенесённую базу. Удалить CANONICAL_URL только при готовности сервера стать основным.
4. Развернуть ровно одну Machine. Проверить HTTPS /healthz (200), приватный API без входа (401), состав заявок, права SQLite и подключения. Managed Postgres для этого приложения не используется.
5. В Meta проверить OAuth callback: https://ugc-creator-keshanovi4.fly.dev/auth/threads/callback .
6. Переключить webhook и меню командой node scripts/setup-telegram.mjs --replace-webhook. Прежний worker больше не запускать.

Официальный CLI: fly config validate --strict; fly deploy --remote-only --depot=false --ha=false. Секреты в fly.toml, git и журналы не добавлять. Резервные копии хранить отдельно от исходников и от единственного диска сервера.
