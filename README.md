# ugc_creator · SNEG Creator Desk

Автопостинг в Threads, короткая анкета, предварительный отбор с ИИ и понятная очередь кандидатов для менеджера в Telegram.

**Threads → анкета → оценка ИИ → уточнение → выбор менеджера → ручная передача товара.**

UGC и охваты оцениваются отдельно. Менеджер работает с одной обновляемой подборкой и карточкой кандидата: смотрит портфолио, задаёт вопрос и принимает решение. Логистика, адреса и отслеживание посылок в приложение не входят.

## Быстрый запуск интерфейса

Нужен **Node.js 24.2+**. У приложения нет внешних npm-зависимостей.

```powershell
git clone https://github.com/keshanovi4/ugc_creator.git
cd ugc_creator/sneg-ugc
npm start
```

Откройте http://127.0.0.1:3000. Без `.env` и `NODE_ENV=production` запускается локальное демо с вымышленными анкетами. Демо не проверяет личность и предназначено только для локального просмотра.

Для рабочего бота задайте production-переменные по [инструкции размещения](sneg-ugc/DEPLOY.md). Шаблон — [sneg-ugc/.env.example](sneg-ugc/.env.example). База, токены и подключения в GitHub не публикуются; после клонирования их нужно настроить отдельно.

Рабочий вход — [@sneg_ugc_bot](https://t.me/sneg_ugc_bot). Приложение развёрнуто в отдельном [проекте SNEG на Railway](https://railway.com/project/5b5a5ac4-d38a-48d9-b09f-c12109fe6988), кабинет — [sneg-production.up.railway.app](https://sneg-production.up.railway.app). Используется одна активная база с SN-0001 и SN-0002 на постоянном диске. Локальный обработчик остановлен; работа бота не зависит от компьютера. Открытие кабинета начинается со всех новых заявок; поиск по номеру работает по всей базе.

## Что находится в репозитории

| Каталог | Содержимое |
| --- | --- |
| `sneg-ugc/dist/` | Адаптивный интерфейс, анкета, критерии отбора, локальные шрифты |
| `sneg-ugc/server/` | Node.js API, SQLite, роли, Telegram, Gemini/Ollama, Threads OAuth и публикации |
| `sneg-ugc/scripts/` | Проверка сборки, резервирование и настройка Telegram |
| `sneg-ugc/test/` | Проверки процесса и серверных интеграций |
| `tools/` | Контроллер локального запуска Windows и его проверки |
| `UGC-*.md` | Аудит, результаты проверки, инструкции владельцу и менеджеру |

## Проверки

Из каталога `sneg-ugc`:

```powershell
npm test
npm run build
```

Из корня репозитория:

```powershell
node --test --test-isolation=none tools/pilot.test.mjs
```

Проверены 49 сценариев приложения и 7 сценариев запуска, включая синтетический пакет из 400 анкет, глобальный поиск номера, ограничение уведомлений и безопасное отключение второй базы. В автоматических тестах внешние API подменены. Проверка с двумя Telegram-аккаунтами, ответом Gemini и отдельной публикацией Threads описана в [отчёте](UGC-QA-2026-10-27.md).

`UGC-start.cmd` — резервный локальный способ запуска, для действующего бота на Railway он не нужен. Контроллер откажется перехватывать уже подключённый к Railway webhook. Для отдельного локального окружения нужны официальный клиент Microsoft Dev Tunnels в `tools/devtunnel.exe` и приватный файл `sneg-ugc/data/pilot-setup.json`; эти файлы не входят в репозиторий. Старые технические имена файлов сохранены для совместимости и сохранности установленной базы.

Имена и данные демонстрационных анкет вымышлены. Секреты вводятся в переменных окружения или в защищённых полях кабинета; рабочую базу и резервные копии храните отдельно от исходников.
