# Размещение Creator Desk

Для бесплатного теста использовать корневой `UGC-start-pilot.cmd`: локальный Node.js + SQLite + короткий Microsoft Dev Tunnel. Railway и домен для такого теста не нужны. Подробная настройка Meta — в OWNER-CHECKLIST.md.

Для постоянного сервера:
1. Node.js 24+, постоянный диск, HTTPS и постоянный PUBLIC_URL.
2. Скопировать .env.example в .env. Указать BOT_TOKEN, BOT_USERNAME, ADMIN_IDS, TELEGRAM_WEBHOOK_SECRET и SESSION_SECRET. Для двух секретов использовать разные случайные значения, соответственно минимум 24 и 32 символа.
3. Установить DEMO_MODE=false и PILOT_MODE=false. Указать DATABASE_PATH на постоянном диске, BACKUP_DIRECTORY в отдельном постоянном каталоге. INTEGRATION_SECRET сохранить неизменным; по умолчанию используется SESSION_SECRET.
4. Запустить `npm start` под менеджером процессов или контейнером. Ежедневно запускать `npm run backup` с теми же переменными среды. Проверять восстановление копии.
5. После доступности HTTPS выполнить `npm run telegram:setup`. Скрипт проверяет существующее подключение; чужой webhook без явной замены не перезаписывать.
6. Открыть кабинет владельцем из Telegram. В настройках утвердить условия набора. Подключить Meta и, при необходимости, Gemini.
7. На тестовых аккаунтах проверить путь от анкеты до решения менеджера. Публичный API /api/session без сессии должен возвращать 401, кандидат не должен видеть чужую анкету.

MANAGER_IDS — дополнительные Telegram ID менеджеров через запятую. Администратор настраивает сервисы; менеджер разбирает анкеты и готовит посты. Других служебных ролей нет.

Посты и обработчик очереди работают только пока запущен процесс. После смены PUBLIC_URL обновить webhook и OAuth Redirect URI в Meta. После смены аккаунта Threads старые запланированные посты требуют повторного подтверждения.

Секреты сервисов можно вводить в рабочем кабинете: они шифруются в SQLite. База, ключ шифрования и резервные копии не должны публиковаться со статическим демо.

Альтернатива облачному ИИ — локальная Ollama: AI_PROVIDER=ollama, AI_MODEL и OLLAMA_URL. В Docker localhost означает сам контейнер; использовать адрес доступного сервиса внутри сети. Публичный доступ Ollama не требуется.
