## Интерфейс и команда

- Три вкладки: новые, ждём ответ, выбранные. Рекомендации и «Мои» — фильтры; история — отдельная кнопка. Поиск охватывает базу.
- Компактная очередь, гротеск в именах, focus поиска, клавиатурные стрелки вкладок. Работы перед оценкой; подробности раскрываются.
- После решения открывается следующий кандидат. «В работе у…» предотвращает решения другого менеджера; владелец может освободить заявку.
- Раздел «Команда»: выдача/отзыв доступа без redeploy, отдельное право публикации Threads, журнал изменений. Права меняются и в открытых сессиях.
- Кандидат редактирует сведения до выбора и отзывает заявку. Изменение повторно оценивается. Есть русские/казахские подписи анкеты; бриф остаётся на языке бренда.
- Ошибки ссылок возле поля; больше трёх ссылок не обрезаются молча. Занятость при сохранении; сетевой сбой не очищает форму.
- Threads: итоговый текст со ссылкой, счётчик 500 символов, аккаунт, местное время, ручная сверка.
- Экран состояния: failed-задания, возраст очереди, последние успешные действия, ошибки доставки, повтор оценки. Повтор Telegram после неизвестного результата следует применять после проверки: сообщение может повториться.

## Эксплуатация и проверки

Ежедневная SQLite-копия создаётся штатным backup API, проверяется quick_check; сохраняются последние 14 файлов. Владелец создаёт/скачивает копии в кабинете. Новые, уточняемые и выбранные анкеты не удаляются. Удаление закрытых анкет по сроку отдельно включается владельцем и по умолчанию выключено. Технические повторы и завершённые задания очищаются через 30 дней.

Фильтрация, сортировка, пагинация и счётчики перенесены в SQL. Проверка запрещает неограниченный `store.all()` для списка и overview. На 72 000 синтетических анкетах (SQLite в памяти, локальный Windows/Node 24.22.1) медиана первой страницы — 328 мс, глубокой страницы — 1266 мс, поиска — 1336 мс, счётчиков — 401 мс. Это не нагрузочное испытание Railway; поиск по большой истории остаётся дороже простой очереди.

73 автоматических сценария приложения, включая 24 новых; 7 проверок локального контроллера; проверка сборки. Внешние API подменены. Проверена миграция старых таблиц без потери записей. Сохраняется одна реплика SQLite, один Volume и webhook Railway. Рабочие кандидаты не использовались для изменения решений; новые реальные Threads-посты не создавались.

Браузер проверяет SQLite в памяти: страницы, черновик/перезагрузка, редактирование, назначение, состояния, мобильная карточка. Актуальные снимки локально в `sneg-ugc/screenshots/`, без рабочих заявок. Запуск регрессий из корня: `node tools/audit-probes-2026-10-28.mjs`. Полный набор: `npm test` из `sneg-ugc`.

## Оставшееся ограничение размещения

Railway API отклонил снимок и расписание: `Manual backups and backup schedules are only available for Pro workspaces`. Тариф не менялся. **Копии приложения на том же Volume не защищают от потери всего диска.** Отдельную копию можно скачать; для автоматического хранения вне Volume нужно включить Pro-снимки или подключить выбранное владельцем внешнее хранилище. Это требует решения по размещению.
