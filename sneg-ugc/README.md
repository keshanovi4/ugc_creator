# СНЕГ* · Creator Desk

Рабочая цепочка: **Threads → анкета в Telegram → предварительный отбор → решение менеджера → ручная отправка товара**.

В приложении три раздела: «Отбор», «Threads», «Настройки». Логистики, адресов, треков, перевозчиков и приёмки контента нет. После выбора менеджер договаривается с кандидатом в Telegram; при желании отмечает «Товар отправлен».

## Интерфейс

Тёплая бумага, глубокий зелёный графит, один приглушённый оливковый акцент. Заголовки — Cormorant Garamond, рабочий текст — Manrope. Шрифты хранятся локально с лицензиями OFL. Очередь построена строками, на телефоне — нижняя навигация и карточка с закреплёнными решениями.

Стартовая очередь — «Новые заявки»: все новые анкеты, подходящие первыми. Дополнительные очереди — рекомендации, уточнения, выбранные, история. Поиск работает по всей базе и принимает номер с пробелом или без дефиса. Есть отдельный фильтр UGC/охваты, причины приоритета и история решения. Кандидат заполняет два коротких шага; вопрос менеджера и ответ сохраняются в карточке.

## Запуск без оплаты

В корне рабочего каталога запустить `UGC-start.cmd`, оставить окно открытым, открыть @sneg_ugc_bot и отправить /start. Microsoft Dev Tunnels предоставляет HTTPS к локальному порту 3100. Компьютер должен оставаться включённым.

Для независимого локального демо:
```powershell
npm start
```
Открыть http://127.0.0.1:3000. Node.js 24+. Демо использует отдельную SQLite-базу; опубликованная статическая демонстрация хранит вымышленные данные только в браузере.

## Подключения

Threads: в рабочем кабинете открыть «Threads», создать Meta app со сценарием Access the Threads API, добавить адрес возврата из кабинета, сохранить Threads App ID/Secret и нажать «Войти в Threads». Для приложения Meta в режиме разработки добавить аккаунт бренда в роли Threads Tester и принять приглашение. Запрашиваются только threads_basic и threads_content_publish. Альтернатива — проверенный Threads User Access Token. При подключении проверяются профиль и право публикации. Подробнее: [настройка владельца](OWNER-CHECKLIST.md).

ИИ: «Настройки» → ключ Google AI Studio → «Проверить и подключить». Ключ сохраняется только после ответа модели. Если модель не указана, сервер ищет доступную текстовую Flash. Бесплатные лимиты зависят от аккаунта и модели; 400 бесплатных запросов ежедневно не гарантируются. Поддерживается и локальная Ollama через серверную конфигурацию.

Модель отвечает по JSON Schema. Для UGC ей не передаются просмотры, подписчики и размер аудитории; для охватов эти признаки передаются отдельно. Все сведения об опыте помечены как заявленные. Имена, Telegram ID, контакты, ссылки и свободный текст анкеты в модель не отправляются. Оценка ИИ не меняет решение менеджера.

Telegram и ИИ обрабатываются независимыми очередями: медленный ответ модели не останавливает кнопки менеджера. Входящие действия Telegram имеют приоритет перед массовыми подтверждениями анкет. Ответ кандидата показан в его карточке; устаревший вопрос не отправляется молча, а последнее решение закрывает старую карточку пустым состоянием.

Без ключа интерфейс явно пишет «По анкете». Правила и модель не смотрят видео и не подтверждают статистику. Для UGC подписчики не являются критерием; охваты оцениваются отдельно. Модель получает только структурированные признаки без имён, контактов, ссылок и заметок. Решение принимает менеджер.

## Telegram

Менеджеру обновляется одна подборка. Входящие анкеты обновляют её не чаще раза в пять минут; после решения менеджера пересчёт идёт без этого ожидания. Отдельное уведомление о новых анкетах приходит сразу, затем группируется с интервалом 15 минут. Кнопка «Разобрать кандидата» открывает одну обновляемую карточку с работами и решениями. Уточнение можно написать прямо боту; кандидат отвечает туда же. Нет автоматического одобрения по баллу.

Очередь Telegram проверяется каждые 2 секунды. Между началами запросов ИИ выдерживается не менее 5 секунд; одновременно выполняется одна оценка. Параметры: WORKER_INTERVAL_MS и AI_MIN_INTERVAL_MS. Быстрые кнопки не увеличивают темп запросов модели.

Открытая карточка обновляет текст и версию кнопок при оценке ИИ, уточнении и ответе кандидата. Пока ожидается ответ, кнопки выбора скрыты. Если менеджер всё же нажал старую кнопку, бот обновляет карточку и предлагает проверить новые данные; решение автоматически не подтверждается.

## Надёжность

SQLite WAL, уникальность анкеты на человека и кампанию, идемпотентные операции, контроль версии при одновременном разборе. Подписанный вход Telegram и серверные роли. Секреты подключений зашифрованы AES-256-GCM; ключ берётся из INTEGRATION_SECRET или SESSION_SECRET. Не менять его без повторного подключения сервисов.

Посты создаются в черновиках, публикуются по расписанию при работающем сервере. План привязан к аккаунту. При потере ответа publish статус «Проверьте аккаунт» не допускает автоматического повтора. Реальная публикация требует подключения аккаунта Meta; в демо она выключена.

## Проверки и файлы

```powershell
npm test
npm run build
npm run backup
```

- `dist/views.mjs`, `dist/app.mjs`, `dist/style.css` — экраны и поведение.
- `dist/domain.mjs` — анкета, критерии и решения.
- `server/service.mjs` — права, очередь, операции.
- `server/connections.mjs` — защищённое подключение Meta и Gemini.
- `server/worker.mjs` — Telegram, ИИ и расписание Threads.
- `test/workflow.test.mjs` — проверки процесса и интеграций с подменёнными внешними API.

Демонстрация не подключена к старой Google-форме: она заменена анкетой Mini App. Существующие ответы формы не перенесены. При необходимости миграция делается отдельным импортом с проверкой Telegram ID.
