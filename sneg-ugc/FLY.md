# Тестовый запуск на Fly.io

Приложение: `ugc-creator-keshanovi4`, регион `ams`, одна Machine shared CPU / 512 МБ, Volume `ugc_data` на 1 ГБ в `/app/data`, HTTP-порт 3000. Настройки находятся в `fly.toml`. Секретов в этом файле нет.

На 27 октября 2026 аккаунт находится в Free Trial. Fly предоставляет 2 часа суммарного времени машин или 7 дней доступа и принудительно останавливает пробные машины через 5 минут. Это ограничение платформы действует и при `auto_stop_machines="off"`; круглосуточная работа требует отдельного решения владельца об оплате. [Условия trial](https://docs.fly.io/about/free-trial).

## Запуск

Из каталога `sneg-ugc` после входа в официальный Fly CLI:

```sh
fly apps create ugc-creator-keshanovi4 --org personal
fly config validate --strict
```

Через Fly Secrets сохранить `BOT_TOKEN`, `ADMIN_IDS`, `SESSION_SECRET`, `TELEGRAM_WEBHOOK_SECRET`. Для существующей базы сохранить исходный `INTEGRATION_SECRET`, либо исходный `SESSION_SECRET`, если отдельный ключ шифрования раньше не использовался. Значения не добавлять в git, `fly.toml` и журналы.

```sh
fly deploy --remote-only --ha=false
```

Один процесс объединяет API, Telegram, оценку ИИ и расписание Threads. Вторую Machine не создавать: копии локальной SQLite не синхронизируются. Managed Postgres не нужен. Fly создаёт отдельный постоянный Volume по `fly.toml`.

`Dockerfile.fly` сначала назначает пользователя `node` владельцем корня Volume, затем запускает приложение от `node` через `su-exec`. Инициализация не меняет права произвольных каталогов и не обходит дерево данных рекурсивно. Обычный Dockerfile и защищённый Compose не меняются.

## Проверка и перенос

1. Проверить публичный `/healthz` (200), приватный `/api/session` без входа (401), владельца процесса и запись SQLite на Volume.
2. Для переноса копии тестовой базы первый запуск направить на `/app/data/bootstrap.sqlite` через временный секрет `DATABASE_PATH`.
3. Сделать согласованную SQLite backup работающего локального пилота. Загрузить её через SFTP с режимом 0600 как `/app/data/pilot.sqlite`. Этот файл ещё не открыт сервером.
4. Изменить `DATABASE_PATH` на `/app/data/pilot.sqlite` и перезапустить Machine. Не заменять файл базы поверх открытой SQLite. При старте владелец импортированного файла будет назначен `node`.
5. Проверить заявки и расшифровку подключений через закрытый API. По необходимости подключить Threads/Gemini заново через кабинет.
6. Для постоянного переноса после готовности хостинга остановить локальный worker, сделать финальную копию и переключить webhook командой `node scripts/setup-telegram.mjs --replace-webhook`. До этого локальное подключение Telegram сохраняется.
7. Перед новым входом Threads проверить OAuth Redirect URI Meta: `https://ugc-creator-keshanovi4.fly.dev/auth/threads/callback`. Само наличие копии базы на Fly не меняет callback и webhook.

В бесплатном тесте не переводить постоянный поток на пробную Machine. Не использовать повторные старты или keepalive для обхода лимитов trial.

## Результат проверки 27 октября 2026

Тестовый деплой выполнен: https://ugc-creator-keshanovi4.fly.dev . На Fly запущена одна Machine с Volume 1 ГБ, образ собран по `Dockerfile.fly`. Проверка shell-скрипта выполнена внутри Linux-сборки.

- Публичный HTTPS `/healthz`: 200; приватный API без сессии: 401; закрытая сессия владельца: 200.
- Копия SN-0001 сохранилась после перезапуска: approved, версия 7. Незавершённых заданий нет.
- Реальный процесс приложения имеет UID 1000, SQLite принадлежит UID 1000, режим файла 0600, integrity_check=ok.
- С сервера получены реальные ответы Telegram getMe (@sneg_ugc_bot), Threads me (@ugc_pilot_lab_2026) и Gemini (recommend на вымышленной анкете).
- Владельцу отправлена отдельная кнопка «Открыть Fly · тест»; Telegram подтвердил отправку. Она открывает копию кабинета, её решения не синхронизируются с локальной базой.
- Текущий webhook Telegram на Fly не переводился. С отдельного разрешения владельца callback Fly добавлен в Meta; также сохранён callback восстановленного локального туннеля, адрес истёкшего туннеля удалён. Сохранение обоих адресов проверено после перезагрузки настроек. Платёжный метод не добавлялся.
- Временный сборщик Fly после сборки остановлен. Ограничения бесплатного trial сохраняются.

При финальной проверке старый Microsoft Dev Tunnel уже был удалён по истечении срока и возвращал 404. С отдельного разрешения владельца локальный пилот перезапущен с новым туннелем на 7 дней: https://q2pzb6pc-3100.inc1.devtunnels.ms . Проверены HTTPS 200, API без входа 401, сохранение двух подключений; меню и подборка Telegram обновлены. Локальный процесс должен оставаться запущенным.

Перед настоящим набором требуется утверждение условий и переход с `PILOT_MODE=true` на рабочий режим. Резервные копии на том же диске не заменяют отдельную защищённую копию.
